**Verdict first.** The libxml2 branch carries two correctness regressions that the test suite cannot see: its error handler is never wired, and the streaming path rejects any single `<binary>` text node above about 10 MB. The pugixml XMLFile path fails the stated constraints on memory and malformed-input rejection and should be scoped to the fragment decoder, where it is the fastest. The Expat branch is the cleanest adapter but the slowest. All three adapters pay for the same thing on the hot path: base64 payload is widened to UTF-16 byte by byte and then narrowed again. The harness reports post-join RSS rather than peak, and it times a byte-wise digest together with parsing.

## High-confidence findings

1. **libxml2 `XMLFile.cpp`, `parse`: structured error callback is dead code.** `xmlSAXVersion(&sax, 1)` sets `initialized` to 1. libxml2 copies only the SAX1 prefix of the handler struct into the context when `initialized` is not `XML_SAX2_MAGIC`, and it routes `serror` only under that magic. So `LibxmlState::error` never runs, well-formedness errors print to stderr through the generic handler, warnings never reach `handler->warning`, and the thrown message is the generic "libxml2 rejected XML input" without line or column. Change: call `xmlCtxtSetErrorHandler` on the context with the state pointer and remove the `serror` assignment. Risk: none to parsing. Falsify: parse a file with a mismatched end tag. If the exception text already carries the libxml2 message and line, and stderr is empty, this is wrong.

2. **libxml2 `XMLFile.cpp`, `parse`: no `XML_PARSE_HUGE` on the streaming path.** The push parser must buffer a complete text run before delivering it, and `xmlParseChunk` raises `XML_ERR_RESOURCE_LIMIT` once pending input exceeds the 10 MB lookup limit; the character-data parser has the same text-length cap. One `<binary>` above roughly 10 MB of base64, about 0.9 M uncompressed 64-bit points, fails in `load` and `transform` while Xerces, Expat and pugixml accept it. The fragment decoder in the same branch sets HUGE for exactly this reason, so the two libxml2 paths disagree. Change: add HUGE and keep `xmlCtxtSetMaxAmplification` at 5 plus `NO_XXE`, mirroring the decoder. Risk: HUGE raises depth and name limits; entity amplification and XXE protection are unchanged. Falsify: generate one uncompressed spectrum with 1.2 M double points and load it. Expect a ParseError now and success after.

3. **pugixml `XMLFile.cpp`, `parse_` and `parseBuffer_`: enforced encoding is cached in a function-local static.** The static initialises once per process, so the first enforced encoding wins for every later file, and the transcoded string leaks. The other two branches convert per call. Change: use `sm.convert` as they do. Falsify: enforce ISO-8859-1 on one file, then UTF-8 on a file containing a four-byte sequence. The second must decode correctly.

4. **pugixml `XMLFile.cpp`: malformed-input rejection and encoding semantics are not preserved.** pugixml accepts duplicate attributes, keeps undeclared entity references as literal text, passes invalid UTF-8 bytes through, and `encoding_auto` ignores the declaration's encoding attribute, so an ISO-8859-1 file is read as UTF-8 and silently mangled. Xerces, libxml2 and Expat reject or honor each of these. There is no parse flag to fix this. Change: restrict pugixml to the fragment decoder, which only sees already-structured data, or document the regression explicitly. Falsify: four negative inputs, one per case, run across all branches and the Xerces baseline.

5. **pugixml `XMLFile.cpp`, `parse`: avoidable memory on top of the O(file) DOM.** The input is accumulated with `std::vector<char>::insert`, which doubles capacity and transiently holds old and new buffers, so capacity reaches twice the file size for the largest input. Every text and attribute value then goes through `pugi::as_wide` into a four-byte wide string and then a `u16string`, three copies of each base64 block. Change: for plain files reserve from `std::filesystem::file_size` or use `xml_document::load_file`; replace `as_wide` with the direct UTF-8 to UTF-16 helper the other branches use. Risk: none. Falsify: VmHWM on one reader before and after; expect a drop of roughly one file size at peak. The result is still O(file), so this does not make the streaming path viable.

6. **libxml2 and pugixml `IndexedMzMLDecoder.cpp`, `parseOffsets`: raw `new[]` leaks on exception.** `stringToStreampos` throws ConversionError out of `domParseIndexedEnd_` and `delete[]` is skipped. The Expat branch already uses `unique_ptr`. Falsify: index with a non-numeric offset under LeakSanitizer.

7. **Index tail failure semantics diverge across branches.** On a malformed tail libxml2 returns -1, which callers treat as "no usable index", while Expat and pugixml throw ParseError from `domParseIndexedEnd_`. Callers see different control flow for the same input. Change: pick one; the baseline behaviour is the -1 return. Falsify: open a file whose index tail is truncated mid-element in each branch and compare whether `openFile` returns false or throws.

8. **`XMLAttributes::value(const char*)` builds a Xerces transcoder per lookup in all three branches.** Each call constructs `xercesc::TranscodeFromStr`, which allocates a transcoder object. mzML mostly uses UTF-16 constant names so it is shielded, but featureXML, idXML and consensusXML handlers use narrow names on every element. Change: if all bytes are below 0x80, widen into a stack `char16_t` buffer and skip the transcoder; keep the fallback for non-ASCII. Falsify: count transcoder constructions or profile a large FeatureXMLFile load.

9. **Adapter character-data path transcodes twice with scalar loops.** libxml2's `utf16` has no `reserve`, so the 20 to 40 KB base64 runs grow by repeated reallocation; Expat's version reserves but still loops byte by byte with `push_back`. Both then call `MzMLHandler::onCharacters`, which narrows the same bytes again through `appendASCII`. Base64 is about 95 percent of the file. Change: scan for any high bit, `resize` once, widen in a plain index loop the compiler vectorises, and keep a scratch `u16string` in the state struct so no allocation happens per callback. Non-ASCII runs take the existing path, so Unicode semantics are untouched. Falsify: a perf profile showing the `utf16` share before and after, plus one-reader stream time.

10. **Per-element allocation churn in the start callbacks.** libxml2 allocates a vector of `u16string` pairs per element; Expat allocates a vector of strings plus a pointer vector; both allocate the end-tag name again, which exceeds SSO for names like `binaryDataArray`. libxml2's SAX1 path additionally duplicates every attribute value inside libxml2 before the callback sees it. Change: scratch arena in the state struct; for libxml2, move to `startElementNs`, which delivers attribute value spans without copies, and rebuild the qualified name from prefix and local name. Falsify: malloc calls per element, and the 96-worker Linux throughput, where allocator contention matters more than on one core.

11. **Harness `benchmark.cpp`: RSS is resident-after-join, not peak.** `currentRssBytes` runs after `threads.clear`, so transient parser buffers are already freed and what remains depends on allocator retention. macOS keeps MADV_FREE pages resident until pressure, and glibc does not trim fragmented arena interiors, so the pugixml numbers mix peak and retention artefacts. Change: add `ru_maxrss` on macOS and `VmHWM` from `/proc/self/status` on Linux, and report both. Falsify: compare the two on the stream mode; if they agree within a few percent, the current numbers are fine.

12. **Harness: the digest is inside the timed region.** `Digest::word` runs a byte-wise FNV step over 16 bytes per point, about one billion steps for the largest input, identical for every parser. It compresses relative differences. Change: add a counting-only consumer mode for timing and keep the digest mode for the equality check so the stored snapshots remain valid. Falsify: time the digest alone over a loaded experiment; if it is under 5 percent of the Xerces stream time, this does not matter.

## Hypotheses and lower-priority items

- **Expat rejects encodings outside its four built-ins.** No unknown-encoding handler is installed, so `windows-1252` or `ISO-8859-15` declarations fail with an unknown-encoding error where Xerces and libxml2 succeed. Falsify with a declared windows-1252 file containing a byte above 0x7F.

- **Fragment decoders create a parser per query.** libxml2 builds a dictionary and input per `xmlNewParserCtxt`; Expat draws a hash salt and copies the fragment into its own growing buffer. A `thread_local` parser reset with `xmlCtxtReset` or `XML_ParserReset`, and a single `XML_GetBuffer` copy for Expat, may close part of the gap to pugixml on the 2048-query path. Thread safety is preserved because the state is per thread.

- **64 KiB read chunks.** Fewer, larger reads cut syscalls and per-chunk parser overhead. Expect a few percent at most.

- **pugixml `parse_ws_pcdata` doubles the node count.** `parse_ws_pcdata_single` would drop inter-element whitespace nodes if no handler depends on them. This changes the callback sequence versus Xerces, so verify with the full handler test set before relying on it.

- **pugixml fragment framing scanner is a hand-rolled tag tokenizer.** It handles quotes, comments, CDATA and PIs, but any other `<!` construct breaks framing and causes a false rejection. Add tests for attribute values containing `>` and `/`, CDATA containing `<`, and a comment before the root.

- **Expat `MzMLSpectrumDecoder.cpp` keeps the dead Xerces DOM `handleBinaryDataArray_`.** It still compiles and pulls Xerces DOM headers. Delete it.

- **libxml2 index decoder requires `indexList` as a direct child of the synthetic root.** The Xerces baseline and the pugixml XPath search any depth. Real writers put it directly under the root, so this is low risk.

- **OpenMP supplement.** The warmup on the main thread leaves an idle team of the same size as the reader team. Under an active wait policy that team burns CPU inside the timed region. Set `OMP_WAIT_POLICY=passive` or run the warmup inside the worker.

- **Harness query seeding.** Every worker replays the same random sequence, so the concurrent numbers benefit from shared page and CPU cache. Per-worker seeds would be more honest but would require a worker-independent equality check.

- **Common `MzMLHandler::populateSpectraWithData_`.** The catch-all branch writes `error_message` outside the critical section. Pre-existing and benign.

## Top three optimizations by expected impact

| Rank | Change | Why it should matter | How to measure |
|---|---|---|---|
| 1 | Finding 9: ASCII fast path with scratch buffer in both `utf16` helpers, optionally an additive UTF-8 character callback that `MzMLHandler` overrides for `binary` | Xerces transcodes once with an optimised reader and still beats both adapters by about 2 s on 1 GiB; the adapters' only extra work on 95 percent of the bytes is this loop plus the reverse conversion | One-reader stream time and `utf16` profile share |
| 2 | Finding 10: scratch arena for names and attributes; libxml2 on `startElementNs` | Removes several heap allocations per element and libxml2's internal attribute duplication; allocator contention is the plausible reason all three converge at 96 workers | Malloc count per element and 96-worker files per second |
| 3 | Finding 5 plus scoping: exact-size input buffer and direct conversion in pugixml, then restrict pugixml to the fragment decoder | Cuts about one file size from peak, but nothing makes a whole-file DOM bounded; the fragment path is where pugixml wins | VmHWM on the whole-load path and the 2048-query time |

Findings 1 through 3 are correctness fixes that must land before any before-and-after timing is comparable. The negative conformance set from findings 2, 4 and 7 should be added to the common harness and run against the preserved snapshots as well as the new builds.
