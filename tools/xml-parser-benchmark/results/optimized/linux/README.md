# Optimized Linux rerun

This run uses the same ibminode05 hardware, CPUs 0–95, parser versions, Release `-O3 -DNDEBUG` C++23 settings and seven byte-identical inputs as the original Linux evaluation. CPUs 0–95 comprise 64 physical cores and 32 SMT siblings. The original workspace and its copied libraries remain unchanged.

`source-manifest.json` records the exact reviewed Git revisions and copied library hashes for the optimized Xerces control, libxml2, Expat and pugixml. The optimized source repository shallow-fetches exact OpenMS base `77cccda7caf40b46a4919d33748450270eccd565`, then fetches the source bundle containing those four revisions. This preserves the same commit identities used on macOS. Base-relative source patches are retained in `reproduce/`. No tracked source changes outside those exact commits are permitted: each build saves and checks an empty tracked-source status. Timed benchmark/launcher/Python runner source hashes are recorded in the manifest. Configuration retains the disclosed private parser-header overlay and original contrib static-CURL package required by Arrow; these are compiler/dependency-discovery settings, with no additional source patch.

The optimized workspace has a separate source tree, build directory, benchmark executable and library snapshots. It reuses the original private parser installation and inputs through read-only symlinks. The benchmark is rebuilt against the new XMLHandler virtual interface; original executables are never used with optimized libraries. All 25 affected class tests run for every backend, with the relevant focused test included in the same CTest invocation for each prototype (26 total). The three shared benchmark smoke tests run through one CTest entry with an explicit backend snapshot library path. Huge-array equivalence, 44 generic XML conformance cases, 22 schema compilations/195 comparisons, and 12 actual XMLValidator API cases are recorded before timing.

The driver waits until all original timings and final schema checks complete. Builds and correctness checks then run sequentially, followed by 4480 randomized measurements: primary2560, memory960, fixed-work OpenMP320, and default-metadata640. All cells have five repetitions. Input and copied-library hashes, decoded output identities, actual loaded library paths, and final cross-mode equivalence are checked. There are no concurrent builds or reviewer workloads during timing.

Linux peak RSS comes from `wait4.ru_maxrss` in KiB; resident RSS samples `/proc/self/statm` after workers join while retained experiments/contexts remain alive. These accounting methods can differ slightly, so resident RSS can exceed the separately recorded peak. Context estimates include indexes, allocator retention, and thread/runtime costs. The fixed-work benchmark can retain a warm-up OpenMP pool as well as its reader-thread pool: an original OMP96 process naturally showed192 native threads with no inherited thread-limit setting. Reader-worker matrices use OMP1. Hardware/affinity, locale, before/after load, RAM and host-wide swap counters are saved.
